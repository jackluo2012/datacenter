# 商业采购级对标调研（ENTERPRISE-GAP）

- 调研日期：2026-10-11；方法：WebSearch/WebFetch 检索真实招标/中标公告、开源项目官方仓库，逐条对照本仓库代码（`*/rpc/internal/logic/`、`docs/schema/*.sql`、`web/src/views/`）。
- 问题：标价 20 多万的 Java 商业数据中台（README"AD 部分"14 模块清单），我们的开源实现是否真满足需求、能否在企业落地。
- 标注约定：【事实】=有来源或代码可查；【推测】=经验推导；【建议】=行动项。
- 仓库基线【事实】：16 个 go-zero 服务（datasource/metadata/datasvc/catalog/quality/metric/tag/job/ide/ai/standard/mdm/ops/security/theme/sys），49 张 `dc_` 表，Vue3 控制台（theme/security 暂无页面）；Phase 7 已补质量告警/错误数据留样/剖析健康分/API 调用统计与文档。

## 一、结论速览（先回答，后论证）

1. 20-50 万预算位买不到"14 模块全功能平台级交付"：真实公告里 18-95 万的项目都是单场景/少量模块，平台级项目预算在 195 万-2400 万【事实，见 2.1】。
2. 验收看的不只是功能清单：第三方测评报告、等保（二级/三级）、监理、培训、质保期 7×24 是招标标配硬项，本仓库当前全部为 0【事实，见 2.2】。
3. 开源侧已出现两个同路线产品（AllData、qData），功能目录与我们高度重合且免费，"目录对标"本身已无商业价值【事实，见三】。
4. 16 服务中真正达到"企业能用"的只有数据服务 API 一块（7.5/10）；质量/标签/主数据/标准为"试用可用"；集成/可视化/数仓建模为演示级或缺失【评估，见四】。
5. 现在就上企业项目：只能在"MySQL 单源、中小规模、有实施人力"的小场景里交付，且必须旁挂 DataEase/SeaTunnel 补短板【推测，见 5.1】。
6. 距离"可签合同的商业交付"约差 7-10 人月（含实施包），其中 1/3 是文档/测评/信创等非编码项【推测，见 5.3】。

### 2.2 验收硬项（招标文件共性条款）

【事实】来自多份公开招标文件（上海市崇明区大数据平台二期、泸州市"城市大脑"、清华大学供应商服务平台、山东省农业农村厅、铜陵职院等，检索自 zycg.gov.cn、各采购官网，2026-10）：

1. **第三方测评**：需由招标人认可的、具有国家级资质（CMA/CNAS）的测评机构出具书面测评报告；
2. **等保测评**：等保二级或三级，由第三方测评机构执行，投标人承诺配合整改；
3. **监理参与**：验收主体=采购人+中标人+监理单位（如涉及）+第三方测评机构（如涉及）；中标人发出验收申请后 10 日内组织验收；
4. **培训**：投标报价必须包含人员培训（管理端+使用端），写入报价构成；
5. **质保与 SLA**：质保期自现场验收（SAT）合格之日起算，质保期内免费运维；常见要求 7×24 小时支持（远程+电话+现场）；
6. **POC**：金融机构类采购普遍设 POC 测试评分标准（案例：民生银行信用卡中心评分卡建模工具采购，e.sinochemitc.com，2023-11）；业界通行做法：总分 80 分门槛、P0 需求未 100% 覆盖一票否决（CSDN《智慧城市产品选型指南》等）；
7. **交付物清单**：部署文档、用户手册、验收测试报告、培训记录、源码或介质（视合同）。

【事实】本仓库现状对照以上 7 项：无部署/用户手册（docs/ 仅调研与 schema 文档）、无测评/等保材料、无培训材料、无 SLA/运维体系（ops 服务仅归档+审计/登录日志，无监控指标）、无标准 POC 演示脚本（有 demo 目录与 postman 集合）。**7 项中 6 项为零**，这与企业"能不能落地"同样相关。

## 三、开源锚点：谁和我们同台（没有一个开源单体=中台，但有两个"目录重合"的国产项目）

### 3.1 AllData 数据中台（杭州奥零数据科技）——"集成全家桶"路线

来源：https://github.com/alldatacenter/alldata （GPL-3.0，3.1k stars，2026-10 查证）

- 定位"可定义数据中台"，本质是 **Java 胶水层 + 集成成熟开源引擎**：SeaTunnel/DataX/Chunjun（同步）、DolphinScheduler（调度）、Dinky/StreamPark/Flink（计算）、OpenMetadata/Gravitino（元数据）、Datavines（质量）、Datart（BI）、Paimon（湖）【事实】。
- 开源版 GPL、**仅限内部调研，商用须购买会员商业版**（源码购买，创始版/尊贵版分级，价格在腾讯文档不公开：https://docs.qq.com/doc/DVEt2eUV0Q3hyZ3lz ）；商业版 17+ 模块、39+ 核心功能、集成 80+ 开源框架，**支持信创+国产数据库版本**【事实，来自 GitHub/Gitee README 及百度开发者社区转载】。
- 启示【推测】：这正是"20 多万卖源码"市场里的真实竞品形态——**开源引流、源码+授权变现、实施另计**。README 里 AD 商业版的销售方式与此同构。

### 3.2 qData 千数平台（江苏千桐科技）——"自研一体化"路线，与本项目最直接对标

来源：https://gitee.com/qiantongtech/qData （Apache-2.0+商标附加条款：去 logo/OEM 需商业授权；~1.95k stars，2025-05 开源，v1.6.x，22 个发行版；掘金 2025-05-26《千数平台正式开源》）

【事实】模块清单：数据集成（可视化配置，DataX/Spark 双引擎）｜数据开发（Quartz/DolphinScheduler 调度+编排）｜数据建模（标准/分层/分域/主题/逻辑模型/数据元）｜元数据（查看/字段结构/版本/比对/采集任务）｜数据质量（稽查规则）｜数据资产（编目/标签/详情/查询）｜数据查询（SQL 在线查）｜数据服务（表/SQL 封装 API+在线测试+调用日志+应用管理）｜AI 智能问数（Text2SQL+智能图表）｜基础管理｜系统管理（用户/角色/菜单/部门/岗位/字典/参数/公告/日志）。技术栈 Spring Boot 2.5.15 + Vue3，**支持 MySQL/PostgreSQL/达梦8/人大金仓**；有专业版（pro-demo.qdata.tech）。

【推测】对照结论：qData 用约 1.5 年把"数据中台全家桶"目录做到了免费开源且开箱可跑（含信创库适配），说明——
1. 这条产品路线市场真实存在（否则不会有两家公司+AD 商业版同时做）；
2. **功能目录本身已无商业价值**：甲方用 20 万预算能同时拿到我们的开源版、qData、AllData 开源版，谈判焦点必然转向"深度、实施、服务"；
3. 我们的差异化只剩：Go 技术栈（资源占用/交付轻量）、beid 多租户、OneService 管控深度（签名/限流/授权/脱敏/审计一条链）、AI 语义层（NL2Metric 而非裸 Text2SQL）。

### 3.3 与经典开源组合的关系

【事实】深度维度我们仍全面落后于单点冠军：质量规则 6 条 vs Datavines 27 条（https://github.com/datavane/datavines ）；DS OpenAPI 仅封装 6 类端点 vs 全量（https://github.com/apache/dolphinscheduler ）；元数据 1 类连接器/表级血缘 vs DataHub 80+ 连接器/列级血缘（https://datahubproject.io/docs/ ）、OpenMetadata（https://github.com/open-metadata/OpenMetadata ）；BI 为零 vs DataEase 全套（https://github.com/dataease/dataease ）。此部分详细逐条对照见 [OPEN-SOURCE-GAP.md](OPEN-SOURCE-GAP.md)，不重复。

## 五、诚实结论

### 5.1 能不能在企业落地产生价值

【推测，基于功能形态与 2.1/2.2 证据】

**能（现在就能签小单）的场景**：
- 数据服务 API 化（OneService）：治理成果出 API 给业务/小程序/第三方，签名限流脱敏审计齐全——这是甲方高频刚需，也是我们唯一超过"假设商业版"分值的模块；
- 质量巡检：规则+定时+告警+错误留样+健康分，中小规模 MySQL 数仓完全够用；
- 资产目录+申请审批+元数据定版对比：轻量数据资产普查场景；
- 标签圈群/画像：本仓库自带 To C 用户体系，营销标签场景闭环真实可跑；
- AI 问数（语义层路线）：演示与售前杀手锏，但需按场景调优，不能承诺准确率。
- 适用画像：单 MySQL/少量库、千万行级以内、甲方有自己的技术团队可接手运维、有乙方实施驻场。**满足此画像的 20-50 万小单可以接。**

**不能（会被 POC/验收直接筛掉）的场景**：
- 多源异构大数据量同步与实时 CDC（无集成引擎）；
- 任何以"报表/大屏/自助分析"为验收点的项目（BI 为零）；
- 数仓建模方法论落地（无建模画布/维度建模）；
- 跨系统元数据治理（连接器 1 类、血缘表级手工）；
- 政府/国企信创环境（无达梦/人大金仓/麒麟适配；qData 已支持，见 3.2）；
- 无甲方技术团队、要求 7×24 质保运维的项目（无监控体系+无交付组织）。

### 5.2 距"20 万级商业交付"的硬项（采购验收视角排序）

| 4 | 运维体系：Prometheus/Grafana/Loki 接入 ops，服务/中间件/接口监控达"数据运维"模块验收口径 | 集成+编码 | 0.5-1 人月 |

### 5.3 商业化路线与总工作量【建议】

- **路线**：不做"平台标"（195 万+的盘子我们 12 个月内不具备竞争力），打"**数据服务 API + 质量 + 资产**"三板斧的 20-50 万小单；BI/集成坚决旁挂开源（DataEase/SeaTunnel）不自研，与 AllData 同一打法但以 Go 轻量交付为卖点。
- **总量**：上表 10 项合计约 **7-10 人月**（2 人 × 3-4 个月封闭交付，可达到"小项目可签可验收"状态）；若只做能签单的最小集（#1/2/3/5 + #9）约 4-5 人月。
- **节奏**【建议】：第 1 个月集成引擎+文档包（决定能不能投标）→ 第 2 个月 BI 旁挂+POC 包装+首个种子客户共创（低价换案例）→ 第 3 个月信创/权限补齐（解锁政府单）→ 之后再谈"对标商业版 14 模块"的完整故事。

## 六、一句话回答用户

**20 多万买的本来就不是 14 模块平台，而是"源码授权+浅实施"；我们的开源版在"MySQL 单源、中小规模、数据服务 API/质量巡检/资产目录"这类小场景上现在就能落地产生价值，但集成与可视化两个关键模块为零、6/7 项验收硬项为零，距能投标验收的商业交付还差约 7-10 人月——先把 SeaTunnel/DataX 和 DataEase 旁挂上、把文档和 POC 包装补齐，再谈企业单。**
