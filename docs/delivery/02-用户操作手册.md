## 1. 登录与退出

1. 浏览器打开平台地址，进入登录页（「数据中台控制台」）。
2. 输入**登录名与密码**：
   - 内置管理员：`admin / admin123`（首次登录后立即在「系统管理→用户管理→重置密码」修改）；
   - 其他账号由管理员在「系统管理→用户管理」创建。
3. 点击「登 录」（或回车）。登录成功后进入仪表盘；登录失败按提示检查账号/密码。
4. 登录态说明：token 保存于浏览器 localStorage（键 `dc_token`/`dc_uid`/`dc_username`），有效期 86400 秒（网关 `Auth.AccessExpire`）；过期或被后端判 401 时自动跳回登录页。
5. 退出：右上角头像下拉 →「退出登录」，确认后清除本地登录态并回到登录页。

> 登录页底部提示的 `13800138000/123456` 为遗留 C 端（`/user/login`）演示账号，管理台登录不使用该账号。

## 2. 仪表盘

登录后首页。内容全部来自真实接口，服务未就绪的区块显示占位而不报错：

1. **概览指标卡（4 张）**：数据源总数、数据服务 API 总数、质量规则总数、近 7 日 API 调用次数；点击任意卡片跳转对应模块。
2. **近 7 日 API 调用趋势**：折线图（数据来自 `/datasvc/callstats`），无数据时显示「暂无调用数据」。
3. **表健康分 Top 5（最新分析）**：展示表名、行数、空值率、主键重复、分析日、健康分（<60 红 / 60-80 黄 / ≥80 绿）；数据来自「数据质量→健康分」的分析记录。
4. **快捷入口（6 个）**：登记数据源、采集元数据、发布数据 API、AI 问数、质量监控、SQL IDE，点击直达对应页面。

典型使用：每天进入系统先看调用趋势与健康分，发现红色健康分后到「数据质量→健康分」下钻。

## 3. 业务模块操作指引

### 3.1 数据源管理（一切数据能力的前提）

列表页展示：ID、名称、类型、地址（host:port）、数据库、用户名、状态、负责人、创建时间。

**登记数据源（典型操作流）**
1. 点击「新建数据源」，填写：
   - 名称（必填，如「数仓 MySQL 主库」）；
   - 类型（必选）：mysql / clickhouse / postgresql / hive / doris / starrocks；
   - 主机、端口（默认 3306）、数据库名、用户名、密码、负责人。
2. 保存后列表即出现新记录；**凭证 AES-GCM 加密入库**，列表不回显密码。
3. 点击行内「测试」，返回 `连接成功，延迟 XXms` 或具体错误（账号/网络/库名）。

**编辑**：密码留空表示不修改；名称/类型/地址等可直接改。
**删除**：行内「删除」→ 二次确认；删除后不可恢复（引用该数据源的 API/任务将无法执行，请先确认无引用）。
**筛选**：顶部类型下拉按类型过滤；分页 10/20/50。

### 3.2 元数据管理

列表字段：ID、类型（table/column/dashboard）、名称、FQN、备注、引擎、行数（自动万/亿格式化）、分级、负责人、数据源 ID。

**采集元数据（典型操作流）**
1. 点击「采集元数据」。
2. 填写数据源 ID（必填，即 §3.1 登记后的记录 ID）、库名（留空采集数据源默认库）。
3. 点「开始采集」，系统基于 information_schema 自动登记库表结构，完成后提示「新建表 X 张、字段 Y 个」。
4. 列表自动刷新；可按类型过滤或按名称/FQN 关键字搜索。

补充能力（API 层，暂无页面入口）：表级血缘登记/查询（`/metadata/lineage`）、定版快照与多版本对比（`/metadata/version/*`）。

### 3.3 数据服务（OneService：配置出 API → 注册应用 → 授权 → 发布 → 调用）

页面三个页签：**API 管理 / 调用统计 / 调用日志**。

**① 新建 API**
1. 「API 管理」页签 →「新建 API」，填写：
   - API 名称（必填，如「订单日汇总查询」）；
   - 路径（必填，如 `/api/order/daily`，不可含空白字符，**创建后不可改**）；
   - 模式（**创建后不可改**）：SQL 模式 / 向导模式 / 注册模式；
   - 数据源（必选，**创建后不可改**）；
   - SQL 语句（必填，仅 SELECT 类查询）；
   - 参数定义（可选 JSON，如 `{"date":"string","user_id":"int64"}`，须为合法 JSON）；
   - 缓存 TTL（秒，0 不缓存，最大 86400）、负责人。
2. 保存后状态为「草稿」。
3. 编辑：仅可改名称/SQL/参数/缓存 TTL；页面有醒目提示「路径/模式/数据源/负责人创建后不可修改」。

**② 注册应用**
1. 工具栏「注册应用」→ 填应用名称（必填）、QPS 限流（默认 10）、IP 白名单（可选，逗号分隔）。
2. 注册成功展示 **App ID / App Key / App Secret**；**app_secret 仅此一次展示，必须立即复制保存**。

**③ 授权**
1. 工具栏「授权」→ 选择 API（下拉可搜索）、填写注册返回的应用 ID；
2. 字段脱敏（可选 JSON，如 `{"phone":"mask"}`，对返回列做出口脱敏）；
3. 有效期：勾选「永久有效」或选择过期时间。

**④ 发布 / 下线**
- 草稿 API 点「发布」（二次确认），状态变「已发布」后方可被调用；「下线」后调用被拒绝。

**⑤ 调用（外部系统）**
```
POST http://<网关>:8887/datasvc/execute
Content-Type: application/json

{
  "app_key": "<注册返回>",
  "ts": "<unix秒>",
  "sign": "<hex(hmac-sha256(app_secret, app_key+ts))>",
  "path": "/api/order/daily",
  "params_json": "{}"
}
```
返回 `rows_json`（结果集）、`cost_ms`（耗时）、`cache_hit`（是否命中缓存）。

**⑥ 调用统计 / 调用日志**
- 调用统计：近 7/14/30 天总调用、成功率、平均耗时、缓存命中数，附每日趋势折线与 Top API 条形图；
- 调用日志：按 API ID / 应用 ID / 状态（成功 ok、失败 error、拒绝 denied）过滤，可看错误码、返回行数、耗时、缓存命中、调用 IP、时间。

**⑦ API 文档**：行内「文档」生成该 API 的 Markdown 文档与 OpenAPI 3.0 JSON（可一键复制），供应用方对接。

### 3.4 资产目录

页面左右布局：左侧分类树 + 右侧资产列表。

**建分类**：左上「新建分类」（或树节点悬浮 + 号建子分类）；填上级分类（不选为顶级）与名称（如「交易域」）。

**登记资产（典型操作流）**
1. 「登记资产」→ 填写：
   - 实体 ID（必填，即 §3.2 采集出的元数据实体 ID）；
   - 资产名称（必填）；
   - 所属分类（树选择，可空）；
   - 资产类型：table / dashboard / api / metric；
   - 安全分级：L1 公开 / L2 内部 / L3 敏感 / L4 核心（L3/L4 列表红色/橙色标识）；
   - 可见性：公开 / 私有；备注。
2. 登记后资产出现在右侧列表，按分类/名称过滤浏览。

> 如实说明：资产「申请-审批」（`dc_asset_apply`，RPC 逻辑 applyAsset/listApplies 已实现）当前**未暴露网关 HTTP 路由**（网关仅 `/catalog/category/create|list`、`/catalog/asset/list|tag` 四个接口），页面不提供申请入口；跨团队取数管控如需启用，需在网关补充对应路由（迭代项）。

### 3.5 数据质量（规则 → 任务 → 结果 → 告警 → 错误数据 → 健康分）

六个页签：

**① 质量规则**：「新建规则」填名称（必填）、规则类型、目标表（必填，仅字母/数字/下划线）、目标列、参数 JSON、阈值 JSON、负责人。

| 规则类型 | 目标列 | 参数 JSON |
|---|---|---|
| row_count 行数检查 | 可空 | 无需参数；可配阈值 `{"op":"gte","value":100}` 或 `{"op":"between","value":[100,2000]}` |
| not_null 非空检查 | **必填** | 无需参数 |
| unique 唯一性检查 | **必填** | 无需参数 |
| value_range 值域检查 | **必填** | `{"min":0,"max":100}` |
| consistency 一致性检查 | **必填** | `{"ref_table":"dim_user","ref_column":"id"}` |
| fluctuation 波动率检查 | 可空 | `{"baseline":10000,"ratio_pct":5}` |

**② 质量任务**：「新建任务」填任务名称、数据源（必选）、目标库（可空）、质量规则（**多选，至少 1 条**）、调度 Cron（可选，如 `0 3 * * *`）。行内「执行」立即运行（确认框提示将串行执行绑定规则），完成后弹窗展示最终状态（passed/failed/partial）、规则总数、通过数与通过率；「日志」查看逐条规则执行结果。

**③ 校验结果**：按任务/结果（通过、不通过）过滤，字段含任务 ID、规则 ID、规则类型、检查值、结果、明细 JSON、执行时间。

**④ 告警配置**：「新建通道」→ 类型（钉钉机器人 / 飞书机器人）、Webhook（必填，http(s) 地址）、加签密钥（钉钉 SEC 开头，可选）、最低告警级别（failed=任务全部不通过才告警；partial=存在部分通过也告警）。启用开关实时生效；「发送测试」向机器人发一条测试消息并回显结果。质量任务执行结束按级别自动推送，内容含任务名、状态、通过率与失败规则明细；发送记录见 `dc_quality_alert_log` 表。

**⑤ 错误数据**：校验失败且开启采样的规则产生样本（上限 100 行）；按任务/规则 ID 过滤，「查看样本」以动态表格解析 rows_json 下钻违规行。

**⑥ 健康分**：选数据源、目标库（可选）、表名（必填）、主键列（可选，用于重复检测）→「开始分析」：
- 仪表盘展示健康分（0-100：<60 红 / 60-80 黄 / ≥80 绿）；
- 指标：总行数、列数、空值率、主键重复数；
- 近 10 次健康分趋势折线（含 60 分及格线）；
- 逐列画像表（profile_json 动态列）。
健康分算法：`100 - 空值率×40 - 主键重复占比×30 - 自定义扣分`。

### 3.6 指标管理

列表含英文标识、中文名称、类型（原子/派生）、口径字段、聚合方式、表达式、维度、备注。

**新建原子指标**：「新建指标」→ 英文标识（必填，创建后不可改）、中文名称（必填）、类型选「原子指标」→ 填口径字段（必填，如 `orders.amount`）、聚合方式（sum/count/avg/max/min/distinct）、维度 JSON（如 `["date","city"]`）、备注。

**新建派生指标**：类型选「派生指标」→ 填计算表达式（必填，基于原子指标，如 `sum(orders.amount) / count(distinct orders.user_id)`）；行内「绑定原子」维护派生与原子的引用关系（口径血缘追踪，可多选、回显已绑定）。

**编辑限制**：仅中文名称、表达式、维度、备注可改；类型/口径字段/聚合方式创建后不可改。

派生指标的口径可直接写入数据服务 API 的 SQL 复用（README 能力项），并作为 AI 问数语义层的候选来源（问数返回的「候选对象」即来自元数据与指标检索）。

### 3.7 标签管理（标签对象 → 标签定义 → 打标与画像）

**① 标签对象**：「新建对象」→ 对象类型（user / member / goods）、对象名称（必填）、数据源、数据库、物理表（必填）、主键列（默认 id）。

**② 标签定义**：「新建标签」→ 所属对象（必选）、标签 Key（如 `consume_level`）、标签名称（如「消费等级」）、标签类型（规则标签 rule / 事实标签 fact / 模型标签 model）、规则 SQL（case when 形式的计算逻辑）、刷新周期 Cron（可选）。删除标签不影响已打历史值，仅停止刷新。

**③ 打标与画像**：
- 执行打标：选择对象 →「执行打标」→ 按规则 SQL 批量计算并写入标签值，完成后提示写入行数；
- 对象画像查询：选对象 + 输入主键值（如用户 ID 10001）→「查询画像」，列出该对象的全部标签（Key/名称/值/打标时间）。

标签圈群（Phase 6，`/tag/group/*`：create/run/members）为 API 能力：按标签条件圈选人群并查询成员，供营销/风控场景经数据服务消费。

### 3.8 数据标准（词根 → 字典 → 数据元 → 标准模型 → 落标核对）

**① 词根**：新建词根（名称必填、中文名、类型：通用/修饰/维度/指标词根、备注），编辑/删除/搜索。

**② 标准字典**：「新建字典」填字典编码（如 gender）、字典名称、备注，并在表单内**逐行添加字典项**（编码 + 值 + 排序，至少 1 行）；「详情」查看字典项；编辑时字典项经详情接口回显。

**③ 数据元**：新建数据元（编码、名称必填；数据类型 varchar/int/bigint/decimal/date/datetime/text；varchar/decimal **必须填长度**；decimal 可填小数位；值域字典可选关联 §② 的字典）。

**④ 标准模型**：「新建模型」填模型编码、模型名称、组成数据元 JSON：
```json
[{"element_code":"order_id","required":true,"pk":true},{"element_code":"user_name","required":true}]
```
（数组，每项 element_code 必填且不得重复，required/pk 可选。）「发布」生成版本快照（重新发布版本 +1 并刷新快照）；「快照」查看发布时点的 JSON 定版。

**⑤ 落标核对（典型操作流）**
1. 选**已发布**的标准模型；
2. 选数据源、填库名（可空）与表名（必填）；
3. 「执行核对」→ 系统将表结构与模型数据元逐一比对，输出差异表：列（数据元）、期望类型、实际类型、结果（匹配 / 缺失 / 类型不一致）；
4. 顶部提示「核对通过：N 项全部匹配」或「存在 X 项偏差」；
5. 下方「核对历史」可按模型过滤并「查看差异」回看历史报告。

### 3.9 主数据（模型 → 记录 → 分发）

**① 模型**：「新建模型」填模型编码、模型名称、物理表（留空按模型编码落表）、编码策略（号段 segment / 自增 auto），并**逐行定义字段**（name 必填且不重复；类型 string/int/decimal/bool/date；string/decimal 可填长度；必填勾选；备注）。

**② 记录**：「新建记录」→ 选所属模型（表单下方提示模型全部字段名）→ 业务编码（可点「自动取码」由编码策略生成）→ 记录数据 JSON（键值对，字段须与模型定义一致，多余字段会被拒绝）。记录在「草稿」状态编辑，点「发布」进入正式主数据（重复发布版本 +1）；列表按模型/业务编码过滤。

**③ 分发**：选主数据记录、目标数据源、目标库（可空）、目标表 →「执行分发」。目标表不存在时**按模型 fields_json 自动建表**；重复分发按业务编码幂等覆盖。下方分发列表展示目标库表、状态（pending/success/failed）、信息与时间。

### 3.10 调度管理（对接 DolphinScheduler）

列表：ID、任务名称、源/目标数据源、同步模式（离线批量 offline / 实时增量 cdc）、调度周期、状态（草稿/已部署/运行中/失败）、工作流编码、最近运行。

**创建同步任务（典型操作流）**
1. 「新建任务」→ 任务名称（必填）、源数据源（必选）、目标数据源（可选，缺省同源）、同步模式、表映射 JSON（可选，如 `{"source_table":"ods_order","target_table":"dwd_order","columns":{"id":"id"}}`）、调度周期（Quartz Cron，如 `0 0 2 * * ?`）。
2. 保存后为「草稿」。

**部署**：行内「部署」推送到 DolphinScheduler（幂等创建工作流并上线），成功回显工作流编码；未配置调度器时提示 `调度器未配置：需设置环境变量 DS_BASE_URL/DS_TOKEN/DS_PROJECT`。

**触发**：部署后可「触发」手动运行（draft 状态禁用），回显调度器实例 ID。「状态」查询调度器侧最新实例状态。

**删除**：已部署任务需先在调度器侧下线，否则删除请求可能被拒绝（确认框已提示）。

**调度器连接**：工具栏按钮查看已配置/连通状态、OpenAPI 地址与说明。

> cron 定时调度需在 DS 侧对该工作流提交 schedule（平台存档 cron 并上线工作流，定时提交待联调完善）；任务执行日志见 DolphinScheduler 控制台（http://<DS>:12345/dolphinscheduler/ui）。未接入 DS 时，「内置引擎」提供源到目标的库到库分批同步兜底（MySQL 系，每批独立事务、标识符白名单防注入）；复杂编排（跨流依赖、补数据、失败重试）以 DolphinScheduler 为准。

### 3.11 SQL IDE

左右布局：左侧脚本列表（搜索/新建/删除/分页），右侧编辑器。

**编写与保存（典型操作流）**
1. 「新建」→ 填脚本名称（必填）、执行数据源（必选）、数据库（可选）→ 在 SQL 编辑区输入 SELECT 语句（仅支持查询，带行数保护）。
2. 「保存」→ 首次保存为 v1；**每次保存版本 +1**，列表与编辑器展示当前版本号与「未保存修改」标记。
3. 切换脚本时有未保存修改会提示。

**运行**：设「最大返回行数」（1-1000，默认 100）→「运行」。有未保存修改时提示「保存并执行」（执行基于已保存版本）。结果区展示行数、耗时、截断标记与动态列数据表；仅允许 SELECT，后端超限自动截断。

### 3.12 AI 问数

聊天式界面。工具条开关「自动执行 SQL」：
- **关闭（默认）**：输入自然语言问题（如「昨日订单量是多少」）→ 返回语义层回答、生成 SQL（标注 LLM / 规则来源）、候选对象（来自元数据与指标语义检索，全程留审计 `dc_ask_log`）与耗时。
- **开启**：需再填数据源 ID 与最大行数（≤100）→ 系统生成 SQL 后经 IDE 安全闸自动执行，直接展示结果表格（动态列）、行数、耗时；执行失败显示 run_error。
- 输入框 Enter 发送，Shift+Enter 换行。
- LLM 能力开关：ai 服务配置 `Llm.Enabled`（默认 false，走规则模式；true 时对接大模型生成）。

### 3.13 数据运维（归档 → 登录日志 → 审计日志）

**① 归档任务**：「新建归档任务」→ 任务名称（必填）、数据源（必选）、库名（可空）、源表名（必填，仅字母/数字/下划线）、归档条件（可选 WHERE 片段，白名单校验，如 `created_at < '2024-01-01'`）、归档表（必填，如 `dc_order_log_archive`）、删除源数据（开关：归档后删源 / 仅插入）、批大小（默认 1000）、调度周期（Quartz Cron，可空则手动执行）。

行内「执行」立即运行（勾选了删源的任务确认框会特别警示），弹窗展示归档行数/删除行数/状态；「日志」查看历次执行记录。这是 `dc_*` 日志表治理的页面化手段（清理 SQL 方案另见 03-运维手册 §4）。

**② 登录日志**：按用户名 / 结果（成功、失败）过滤；字段：用户名、用户 ID、IP、User-Agent、结果、信息、时间。对应 `dc_ops_login_log`。

**③ 审计日志**：按资源（如 datasource）、用户 ID 过滤；每行可展开查看 detail_json（路径、query、body 摘要——密码类字段已脱敏为 `******`）。对应 `dc_ops_audit_log`，覆盖全部 POST/PUT/DELETE 管理面写操作。

### 3.14 演示数据（docs/demo/demo_data.sql，可选）

导入后获得一套电商样例（dm_users 500 行 / dm_products 80 行 / dm_orders 1500 行 / dm_order_items 2500 行，确定性生成、可重复执行），可用于：元数据采集演示、AI 问数（「华东地区订单金额 top3 的城市」类问题）、质量规则实验、标签打标与圈群、数据标准核对等。完整 15 分钟演示动线见 `docs/demo/DEMO.md`。

## 4. 系统管理（RBAC）

> 仅 admin 角色或被授权用户可见「系统管理」目录。种子数据内置：角色 admin（全部权限）/ viewer（菜单可见、无按钮权限），账号 admin/admin123。

### 4.1 用户管理

列表：ID、登录名、昵称、手机号、邮箱、角色（标签）、状态开关、创建时间。

**新建用户（典型操作流）**
1. 「新建用户」→ 登录名（必填，2-32 位字母/数字/下划线，**创建后不可改**）、初始密码（必填，6-32 位不含空格）、昵称、手机号（11 位校验）、邮箱（格式校验）、角色（多选）、状态、备注。
2. 保存后账号即可登录管理台。

**常用操作**：
- 编辑：昵称/手机/邮箱/角色/状态/备注；密码留空不修改；
- 重置密码：行内「重置密码」→ 弹窗输入新密码（6-32 位）；
- 停用/启用：列表状态开关即时生效（停用后该用户无法登录）；
- 删除：不可恢复；状态筛选默认「全部状态」（后端约定 -1 为全部）。

### 4.2 角色管理

列表：ID、权限字符、角色名称、状态、备注。

**新建角色（典型操作流）**
1. 「新建角色」→ 权限字符（字母开头 2-32 位，如 operator，**创建后不可改**）、角色名称、状态、备注；
2. 「菜单权限」树：目录（蓝）/菜单（绿）/按钮（橙）三级节点，**严格模式父子独立勾选**（仅勾选节点保存为角色菜单）；
3. 保存后，把角色分配给用户（§4.1），用户重新登录即按角色下发菜单与按钮权限。

**删除限制**：仍有用户引用的角色删除会被拒绝。

### 4.3 菜单管理

树形展示全部菜单（目录/菜单/按钮）。

**新增菜单/按钮**：工具栏或行内「+」→ 填父级（不能选按钮为父级，且排除自身子树防环）、类型（目录/菜单/按钮）、名称（必填）、路由路径、组件路径、权限标识、图标、排序、是否可见。
**权限标识**：格式 `模块:动作`（如 `sys:user:create`、`datasource:collect`、`quality:run`），保存时后端校验格式与防环。内置种子已为 13 个业务模块配好 list/create/update/delete 及专属按钮（元数据采集、服务发布、资产上架、质量扫描、标签圈群、任务执行、脚本运行、AI 提问）。
**删除**：有子节点时先删子节点。

### 4.4 操作日志 / 登录日志

- **操作日志**（系统管理 → 操作日志）：管理面全部写操作审计，按资源/用户 ID 过滤，展开行看请求详情（密码类字段已脱敏）；
- **登录日志**（系统管理 → 登录日志）：按用户名/结果过滤，含用户 ID、IP、User-Agent、成败与信息。

两页与「数据运维」页签同源（`dc_ops_audit_log` / `dc_ops_login_log`），管理员日常巡检建议从这里看异常登录（失败次数突增）与敏感写操作。

## 5. 常见问题（FAQ）

| 现象 | 处理 |
|---|---|
| 登录报「用户不存在」或 401 | 确认 sys.rpc 已部署且 sys.sql 已导入（内置 admin 才会播种）；密码区分大小写 |
| 登录后菜单只有仪表盘 | getRouters 失败（sys.rpc 未部署/网络异常），前端自动降级静态菜单；检查 sys.rpc 与网关 etcd 配置 |
| 页面按钮不显示 | 当前角色无对应按钮权限，联系管理员在「角色管理」勾选按钮节点 |
| 数据服务调用返回 denied | 未授权/授权过期/IP 不在白名单/限流触发；到「数据服务→授权」检查 |
| 质量任务执行完没收到告警 | 告警通道未启用、min_level=failed 而任务状态是 partial、webhook/加签错误——先「发送测试」定位 |
| 标准模型下拉为空 | 落标核对只列**已发布**模型，先到「标准模型」页签发布 |
| IDE 执行报仅支持查询 | IDE 仅允许 SELECT（防误操作），改写为 SELECT 或到调度/归档模块处理写入类需求 |
| AI 问数没有生成 SQL | ai 服务 `Llm.Enabled=false` 时走规则模式，仅对已采集元数据/已定义指标可回答；先完成元数据采集与指标定义 |
| 主数据分发失败 | 看分发列表 msg；确认目标数据源可连、目标库名正确、字段类型兼容 |
