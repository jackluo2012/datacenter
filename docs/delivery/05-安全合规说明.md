# 安全合规说明

> 目的：向采购方/监理方如实说明本平台的安全设计、已具备的控制项、以及需要客户侧（实施环境）补齐的安全基线。
> 依据：GB/T 22239-2019《网络安全等级保护基本要求》第三级（通用要求）逐条对照；实现细节均指向仓库代码位置，可核查。

## 1. 鉴权体系

### 1.1 总体链路

```
浏览器登录 ──POST /sys/login（username+password）──▶ sys.rpc（bcrypt 校验 sys_user）
       ◀── token（JWT HS256，含 uid/username/beid，有效期 AccessExpire=86400s）──
后续请求 ── Authorization: Bearer <token> ──▶ 网关 JWT 中间件（rest.WithJwt，21 组业务路由全覆盖）
       ── x-user-id: <uid>（前端统一携带）──▶ 防越权校验（UserCheckMiddleware：请求头必须与 token 内 uid 一致）
```

> 防越权中间件的挂载范围（routes.go 三组 `rest.WithMiddlewares([Usercheck])`）：`/user/dc/info`、`/votes/enroll`、`/votes/vote`、`/questions` 提交答案等**遗留业务接口**。数据中台管理面接口（datasource/quality 等）当前以 JWT 有效为边界（见 §1.5 如实说明）。

代码位置：

| 控制点 | 代码 |
|---|---|
| JWT 签发与校验 | 网关 `etc/datacenter-api.yaml` Auth 段 + 各路由组 `rest.WithJwt`（internal/handler/routes.go，21 组）；库：golang-jwt/jwt/v4 v4.5.2（修复 CVE-2020-26160 的维护版分支） |
| 防越权 | `internal/middleware/usercheckmiddleware.go`：`x-user-id` ≠ token uid 时拒绝；前端 axios 拦截器统一携带该头（web/src/api/http.ts） |
| 登录口令校验 | `sys/model/password.go`：bcrypt（cost 10，随机盐，`$2a$10$` 前缀） |
| 运维类 BasicAuth | `internal/middleware/admincheckmiddleware.go`：凭据从环境变量 `ADMIN_USER/ADMIN_PASS` 读取，**未配置时拒绝全部请求（fail-closed）**，比对使用 `crypto/subtle.ConstantTimeCompare` 防时序攻击 |

### 1.2 RBAC（对标 RuoYi 模型）

- 数据模型五表（docs/schema/sys.sql）：`sys_user` / `sys_role` / `sys_menu` / `sys_user_role` / `sys_role_menu`；`beid` 字段预留多租户/多站点隔离。
- 菜单三级模型：目录(1) / 菜单(2) / 按钮(3)，按钮挂权限标识 `perm`，格式强制 `模块:动作`（`sys/rpc/internal/logic/saveMenuLogic.go` 正则校验，如 `sys:user:create`、`quality:run`）。
- 种子数据（`sys/model/seed.go`，幂等可重入）：
  - 内置账号 `admin/admin123`（超级管理员角色，**首次登录必须改密**，见 §5 基线清单）；
  - 内置角色 `admin`（全部菜单+按钮）/ `viewer`（全部目录+菜单可见，不含按钮）；
  - 13 个业务模块 × list/create/update/delete + 模块专属按钮（元数据采集、服务发布、资产上架、质量扫描、标签圈群、任务执行、脚本运行、AI 提问）共 60+ 按钮 permission。
- 动态菜单：登录后 `GET /sys/getinfo` 返回 roles/perms/菜单树，`GET /sys/getrouters` 返回路由树，前端 `addRoute` 动态注册；sys-rpc 不可用时降级静态菜单（只读浏览，无按钮权限）。

### 1.3 前端按钮权限（v-perm）

- 指令：`web/src/directive/perm.ts`；用法 `v-perm="['sys:user:create']"`，未持有 perm 的按钮从 DOM 移除（系统管理各页已全面挂载）。
- perms 来源：`/sys/getinfo` 的 perms 集合（后端由用户角色→菜单树→`CollectPerms` 汇聚，`sys/rpc/internal/logic/getInfoLogic.go`）。

### 1.4 数据服务调用鉴权（应用级，与管理台 JWT 隔离）

外部系统调用 `/datasvc/execute` 不使用 JWT，走**应用 HMAC 签名 + 六道闸**（datasvc 服务，OneService 模式）：

```
HMAC 签名校验（sign = hex(hmac-sha256(app_secret, app_key+ts))，防重放依赖 ts）
→ 应用限流（注册时 rate_limit_qps）
→ 授权校验（dc_api_grant：API×应用×有效期×IP 白名单）
→ 参数白名单（params_json 声明外的参数不透传）
→ 结果缓存（cache_ttl）
→ 出口字段脱敏（field_mask，见 §3）
```

未授权/过期/超限/路径不存在分别返回 denied/error 业务码并在 `dc_api_call_log` 留痕（含 IP 与错误码）。

### 1.5 如实说明（当前边界）

1. **接口级按钮鉴权**：按钮权限（perm）当前作用于前端显隐与菜单下发；网关层对管理面接口的强制是「JWT 有效」，perm 未逐接口强校验；防越权中间件仅挂载在遗留业务接口组（/user/dc/info、votes 投票/报名、questions 提交答案）。内网可信部署可接受；如需强制，建议在交付实施中将网关置于零信任网关/堡垒机之后，或采购接口级鉴权增强迭代。
2. **默认口令与密钥**：admin/admin123、JWT AccessSecret、AES EncryptKey 均为仓库默认值，上线前必须更换（见 §5）。
3. **token 无服务端吊销**：JWT 无状态，token 泄露需等自然过期（默认 86400s）；建议生产缩短 AccessExpire 并配合 HTTPS 与最小权限账号。

## 2. 审计

### 2.1 写操作全覆盖审计（网关切面）

- 实现：`internal/middleware/auditlogmiddleware.go`，经 `server.Use` 全局挂载（`datacenter.go`），**所有 POST/PUT/DELETE 自动落审计，GET 不记**。
- 记录字段：uid、username、beid、action（POST=create / PUT=update / DELETE=delete）、resource（路径首段，如 datasource）、resource_id（路径末段数字）、IP（X-Real-IP / X-Forwarded-For 首个 / RemoteAddr 兜底）、path、query、body 摘要（≤500 字节，MultiReader 回填不影响下游解析）。
- **密码脱敏**：body 摘要中 key 含 `password` / `passwd` / `secret` / `token`（大小写不敏感）的字段一律替换为 `******` 后才落库——审计日志不落明文口令。
- 可靠性：异步落库（goroutine），3 秒超时保护 + panic 兜底，审计失败仅记错误日志，**绝不阻断业务请求**。
- 存储：ops 服务 `dc_ops_audit_log`（resource/uid 双索引）；查询入口：「数据运维→审计日志」与「系统管理→操作日志」两处页面。

### 2.2 登录审计

- 管理台登录（`/sys/login`）成功与失败均记录 `dc_ops_login_log`：username、uid、IP、User-Agent、success、msg、时间；查询入口：「数据运维→登录日志」「系统管理→登录日志」。

### 2.3 业务留痕（补充）

| 行为 | 留痕位置 |
|---|---|
| 数据服务每次调用（含 denied） | dc_api_call_log（status/error_code/ip/cost_ms/cache_hit） |
| 质量任务执行结果 | dc_quality_result；告警发送 dc_quality_alert_log |
| AI 问数问答（问题/候选/生成 SQL） | dc_ask_log |
| 主数据分发、归档执行 | dc_mdm_distribution、dc_ops_archive_log |
| 元数据定版快照 | dc_meta_version（版本快照可对比，天然变更留痕） |

## 3. 数据脱敏

### 3.1 脱敏算法（security 服务，`security/rpc/internal/logic/masker.go`）

| 算法 | 行为 | 参数（params_json） | 示例 |
|---|---|---|---|
| mask | 保留前 prefix 后 suffix 个字符（rune 计，中文安全），中间以 mask_char 填充；**长度不足或前后缀重叠时整值掩码**（杜绝短值漏脱敏） | `{"prefix":3,"suffix":4,"mask_char":"*"}`（mask_char 缺省 `*`，必须单字符） | 138****5678 |
| hash | sha256 hex 取前 16 位（不可逆） | 无 | e3b0c44298fc1c14 |
| replace | 整值替换为指定值（允许替换为空串） | `{"replace":"已脱敏"}` | 已脱敏 |
| null | 返回空串 | 无 | （空） |

控制项：
- **算法白名单**：仅上述 4 种，保存脱敏规则时校验（`ErrAlgorithmInvalid`）；未知算法在执行侧 fail-closed 全掩码兜底；
- 规则模型：`dc_sec_mask_rule`（表/列→算法+参数），配套 `dc_sec_level`（L1-L4 分级）、`dc_sec_entity_tag`（元数据实体打分级标签）、`dc_sec_grant`（分级授权）与权限判定接口 `/security/checkperm`；
- 预览接口 `/security/mask/preview`：配置前可对样例值试算脱敏效果；
- 应用点 1（出口脱敏）：数据服务授权时的 field_mask（如 `{"phone":"mask"}`），在 `/datasvc/execute` 结果出口按列脱敏；
- 应用点 2（预览）：管理台经 API 试算，供安全管理员制定规则。

### 3.2 凭证与敏感数据加密

- 数据源凭证（密码）AES-GCM 加密入库（datasource 服务 `EncryptKey`，32 字节密钥），列表/日志不回显明文，编辑留空即不改密；
- 告警通道加签密钥字段（dc_quality_alert_channel.secret）入库存储，接口返回层注意不要在共享屏幕展示；
- 应用 app_secret 仅注册响应返回一次，后续不可查询。

### 4.4 结论（如实）

- **软件层面已满足**：唯一身份标识、bcrypt 口令存储、RBAC 访问控制模型、按钮级权限体系、防越权校验、管理面写操作 100% 审计 + 密码脱敏、登录审计、数据源凭证加密、出口字段脱敏（4 算法白名单 fail-closed）、数据服务调用全链路鉴权与留痕、备份恢复方案。
- **需在实施环境补齐（客户侧/双方联合）**：HTTPS/TLS、密码复杂度与定期更换制度、登录失败自动锁定（或 WAF 策略）、中间件高可用架构、边界防火墙/WAF、主机恶意代码防护、日志外送 SIEM、生产化 DolphinScheduler。
- **建议上线前必做的安全基线**：见 §5。
