# 数据中台部署手册

> 适用版本：main 分支（go-zero v1.10.3 全栈现代化后，2026-10）
> 覆盖范围：单机 Docker Compose 部署、传统（物理机/虚机 + server.sh/restart.sh）部署、前端部署、schema 升级与回滚预案。
> 本手册所有命令、端口、路径、账号均与仓库当前代码一致，可直接执行。

## 1. 部署形态总览

### 1.1 架构与进程

系统由 **1 个 API 网关 + 21 类 RPC 服务 + 4 个中间件** 组成。网关是唯一对外入口（8887），所有前端/外部请求经网关转发到内部 RPC（go-zero etcd 服务发现）。

```
浏览器 / 外部系统
      │  HTTP (JWT 或 HMAC 签名)
      ▼
┌──────────────────┐   etcd 服务发现(2379)
│ datacenter-api   │──────────────┐
│ 网关 :8887       │              ▼
└──────────────────┘   ┌────────────────────────────────────────┐
      │                │ datasource 8085  metadata 8086         │
      ▼                │ datasvc 8087     catalog 8088          │
┌──────────┐           │ quality 8089     metric 8090           │
│ MySQL    │           │ tag 8091         job 8092              │
│ 8.4:3306 │◄──────────┤ ide 8093         ai 8094               │
└──────────┘           │ standard 8095    mdm 8096              │
┌──────────┐           │ ops 8097         theme 8098            │
│ Redis    │◄──────────┤ security 8099    sys 8100              │
│ 8 :6379  │           │ （遗留：user 8080 common 8081 votes 8082 │
└──────────┘           │  search 8083 questions 8084）           │
┌──────────┐           └────────────────────────────────────────┘
│ etcd     │
│ 3.5:2379 │        ┌──────────────────────┐
└──────────┘        │ Elasticsearch 7.17   │
                    │ :9200（search/检索用）│
                    └──────────────────────┘
```

### 1.4 两种部署路线怎么选

| | **路线 A：docker compose（推荐）** | **路线 B：传统部署（server.sh + restart.sh）** |
|---|---|---|
| 覆盖进程 | 4 中间件 + **11 个服务**（网关 + Phase 1-4 的 10 个 RPC） | 4 中间件（docker 起依赖）+ **21 个进程全量**（含 Phase 5-7 六个服务与遗留 RPC） |
| 初始化 SQL | 空库首启自动执行 `sql.sql → phase1 → phase2 → phase3` 共 4 个文件 | 手工 `source` 全部 schema（含 phase5/6/7/sys） |
| 日志 | `docker compose logs` | 各服务目录 `nohup.out` |
| 适用 | 快速交付/演示/POC；**若需 RBAC 登录与 Phase 5-7 功能，需按 §4.5 补齐 6 个服务** | 生产交付全功能（系统管理 RBAC、数据标准、主数据、运维日志、数仓建模、数据安全） |

> **关键差异（务必知悉）**：docker compose 编排与 `Dockerfile` 均只包含 Phase 1-4 的 10 个 RPC + 网关（共 11 个二进制）。`standard/mdm/ops/theme/security/sys` 六个服务**不在 compose 编排内**，而管理台登录（`/sys/login`）、审计日志、数据标准、主数据、归档等功能依赖这些 RPC。全功能交付请使用路线 B，或按 §4.5 在 compose 环境补起这 6 个进程。

## 2. 路线 A：单机 Docker Compose 部署

### 2.1 前置要求

| 项 | 要求 |
|---|---|
| 操作系统 | 任意可运行 Docker 的 Linux（WSL2 亦可） |
| Docker | 20.10+（含 docker compose v2 插件） |
| 硬件 | ≥ 4C8G（ES 已限堆内存 512m；磁盘预留 ≥ 20G，MySQL 数据落 `./data/mysql`） |
| 端口占用 | 宿主机仅需放通 **8887**（唯一对外）；如启用外挂再放通 8088 / 12345 |
| 代码 | 完整仓库（含 `deploy/docker/`、`docs/schema/`、`sql.sql`） |

### 2.2 部署步骤

```bash
cd /path/to/datacenter

# 1. 构建一体镜像（首次较久，golang:1.26-alpine 编译 11 个二进制）
docker compose build

# 2. 启动（mysql 健康检查通过后按序启动各服务）
docker compose up -d

# 3. 查看状态与日志
docker compose ps
docker compose logs -f datacenter-api
```

首次启动空库时，MySQL 容器按文件名顺序自动执行初始化 SQL（容器内挂载映射）：

| 容器内文件 | 仓库源文件 |
|---|---|
| /docker-entrypoint-initdb.d/01-schema.sql | ./sql.sql |
| /docker-entrypoint-initdb.d/02-phase1.sql | ./docs/schema/phase1.sql |
| /docker-entrypoint-initdb.d/03-phase2.sql | ./docs/schema/phase2.sql |
| /docker-entrypoint-initdb.d/04-phase3.sql | ./docs/schema/phase3.sql（含 Phase 3/4 表） |

> 注意：**phase5/phase6/phase7/sys.sql 不会被自动执行**，且镜像内没有这 6 个服务的二进制。仅体验 Phase 1-4 时无需处理；需要全功能请按 §4.5 补齐。

数据持久化：MySQL 数据在宿主机 `./data/mysql`（删容器不丢数据）；DataEase/DolphinScheduler 数据分别在 `./data/dataease/`、`./data/dolphinscheduler/`。

### 2.3 外挂 profile（可选）

```bash
# 可视化 DataEase（Phase 4 决策：可视化不自研，外挂官方镜像）
docker compose --profile viz up -d dataease
# 登录入口 http://localhost:8088（宿主 8088 → 容器 8081）
# 首次初始化密码：DATAEASE_INIT_PASSWORD=DataEase123456，用 admin / DataEase123456 登录后立即改密
# 元数据库复用平台 mysql，首次需一次性建库：
docker exec -it datacenter-mysql mysql -uroot -padmin -e "CREATE DATABASE IF NOT EXISTS dataease DEFAULT CHARSET utf8mb4;"

# 调度联调 DolphinScheduler（Phase 3；standalone 内嵌 zookeeper + H2，重启丢配置）
docker compose --profile ds up -d dolphinscheduler
# 登录 http://localhost:12345/dolphinscheduler/ui （admin/dolphinscheduler123）
```

job-rpc 对接 DolphinScheduler 不走 yaml 配置，读三个环境变量（`job/rpc/internal/logic/dsclient.go`）：

| 环境变量 | 值示例 |
|---|---|
| DS_BASE_URL | http://dolphinscheduler:12345/dolphinscheduler |
| DS_TOKEN | 在 DS「安全中心 → 令牌管理」创建的 API Token |
| DS_PROJECT | datacenter |

在 `docker-compose.yml` 的 `job` 服务下追加 `environment` 段（保留 `TZ: Asia/Shanghai`）后 `docker compose up -d job` 重建生效。

### 2.4 健康检查

```bash
# 1. 容器全部 Up 且 (healthy)
docker compose ps

# 2. 网关存活（未带 token 应返回 401 JSON，说明网关与 JWT 中间件在工作）
curl -i http://127.0.0.1:8887/datasource/list
# 期望：HTTP/1.1 401 Unauthorized

# 3. 管理台登录自检（内置账号 admin/admin123，sys.sql + sys.rpc 就绪后可用）
curl -s -XPOST http://127.0.0.1:8887/sys/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
# 期望返回：{"code":0,"data":{"token":"...","uid":1,...},"msg":""}

# 4. 数据服务签名链路（登记数据源后）
curl -s -XPOST http://127.0.0.1:8887/datasource/create \
  -H 'Content-Type: application/json' \
  -d '{"name":"自检库","type":"mysql","host":"mysql","port":3306,"db_name":"datacenter","username":"root","password":"admin"}'
```

compose 内各依赖容器自带 healthcheck：mysql（mysqladmin ping）、redis（redis-cli ping）、etcd（etcdctl endpoint health）、es（curl 集群健康）。

### 2.5 常见故障排查表

| 现象 | 可能原因 | 排查与处理 |
|---|---|---|
| `docker compose up` 后服务反复重启 | mysql 未健康（首次初始化慢） | `docker compose logs mysql` 观察 init 进度；healthcheck 已设 start_period=30s、retries=12，耐心等待 |
| 网关启动报 `etcd connection refused` | etcd 容器未就绪 | `docker compose ps`；`docker compose logs etcd`；etcd 数据卷异常可 `docker compose rm -sf etcd && docker compose up -d` |
| 登录报 401/用户不存在 | 镜像内**没有 sys.rpc**（管理台登录依赖） | 属预期限制：compose 只编排 11 个服务。按 §4.5 补起 sys.rpc；或改用路线 B |
| `/standard/*` `/mdm/*` `/ops/*` 接口 404/超时 | 对应 RPC 不在 compose 编排内 | 同上，按 §4.5 补起 standard/mdm/ops RPC |
| MySQL 起不来，日志报权限/损坏 | `./data/mysql` 属主非容器 uid（999） | `chown -R 999:999 ./data/mysql`；损坏时从备份恢复（见 03-运维手册 §2） |
| 首次建表缺失（缺 dc_std_* 等） | 初始化仅挂载了 4 个 SQL | 手工补执行：`docker exec -i datacenter-mysql mysql -uroot -padmin datacenter < docs/schema/phase5.sql`（依次 phase6/phase7/sys.sql） |
| ES 启动后 60s 内不健康 | 堆内存/VM 参数 | 已设 `ES_JAVA_OPTS=-Xms512m -Xmx512m`；宿主 `sysctl vm.max_map_count>=262144` |
| `datasvc/execute` 返回签名错误 | app_secret 不对或时间偏差 | secret 仅注册时返回一次；`sign=hex(hmac-sha256(app_secret, app_key+ts))`，ts 为 unix 秒，服务器间校时 |
| 页面能开但接口跨域报错 | 前端 `VITE_API_BASE` 指错 | 前端直连网关（网关已开 CORS），确认 baseURL 为 `http://<网关IP>:8887` |
| 磁盘持续增长 | MySQL 数据 + `dc_*` 日志表膨胀 | 数据目录 `./data/mysql`；日志表清理 SQL 见 03-运维手册 §4 |

## 3. 路线 B：传统部署（server.sh 起依赖 + restart.sh 起服务）

### 3.1 前置要求与依赖版本矩阵

| 组件 | 版本 | 部署方式 |
|---|---|---|
| Go | 1.26+（`go version` 核验） | 宿主机安装（参考 docs/UPGRADE.md 用户空间安装法：`~/.local/go/bin` + `~/go/bin` 进 PATH） |
| Docker | 20.10+ | 宿主机安装（仅用于跑 4 个中间件容器） |
| MySQL | **8.4**（容器 `mysql:8.4`，3306 对外，root/admin） | `server.sh` |
| Redis | **8**（容器 `redis:8-alpine`，requirepass admin，6379 对外） | `server.sh` |
| etcd | **v3.5.21**（容器，2379/2380 对外，数据落 `./etcd/`） | `server.sh` |
| Elasticsearch | **7.17.28**（容器，9200/9300 对外，elastic/admin，数据落 `./elasticsearch/`） | `server.sh` |
| Node.js | ≥ 18（仅前端构建需要） | 宿主机安装 |

### 3.2 部署步骤

```bash
cd /path/to/datacenter

# ---- 第 1 步：起依赖中间件（会先 kill/rm 同名旧容器再重建）----
sh server.sh
# 成功标志：依次输出 mysql/redis/etcd/es 四组容器 ID
# 验证：
docker ps --format '{{.Names}}\t{{.Ports}}'          # 应见 mysql(3306) redis(6379) etcd(2379) es(9200)
docker exec -it mysql mysqladmin -uroot -padmin ping  # mysqld is alive

# ---- 第 2 步：建库并按顺序导入 schema ----
mysql -uroot -padmin
```

```sql
CREATE DATABASE IF NOT EXISTS datacenter DEFAULT CHARSET utf8mb4;
USE datacenter;
SOURCE sql.sql;                      -- 平台基座表（base_member/base_app/app_* 等）
SOURCE docs/schema/phase1.sql;       -- 数据源/元数据/数据服务/资产目录
SOURCE docs/schema/phase2.sql;       -- 质量/指标/标签
SOURCE docs/schema/phase3.sql;       -- 调度/IDE/AI 问数（含 Phase 4 审计表）
SOURCE docs/schema/phase5.sql;       -- 标准/主数据/运维日志（Phase 5）
SOURCE docs/schema/phase6.sql;       -- 数仓建模/数据安全/标签圈群（Phase 6）
SOURCE docs/schema/phase7.sql;       -- 告警/错误数据/健康分/API 调用日志（Phase 7）
SOURCE docs/schema/sys.sql;          -- RBAC 五表（sys_user/sys_role/sys_menu/关联表）
-- 可选：演示数据（电商样例，dm_users 500 / dm_products 80 / dm_orders 1500 / dm_order_items 2500）
SOURCE docs/demo/demo_data.sql;
```

```bash
# ---- 第 3 步：核对各服务配置文件（详见 §3.3）----
# 仓库已自带全部 */etc/*.yaml；如从零开始，复制 *.example.yaml 为正式名后按 §3.3 修改

# ---- 第 4 步：编译并拉起全部 21 个进程 ----
sh restart.sh

# ---- 第 5 步：验证 ----
curl -s -XPOST http://127.0.0.1:8887/sys/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'    # 管理台登录自检
tail -F nohup.out                                     # 网关日志
```

`restart.sh` 实际拉起的进程（`ps -ef | grep -E 'server|datacenter'` 应全部存在）：

common-server、user-server、votes-server、search-server、datasource-server、metadata-server、datasvc-server、catalog-server、quality-server、metric-server、tag-server、job-server、ide-server、ai-server、standard-server、mdm-server、ops-server、theme-server、security-server、questions-server、datacenter-server（网关）。

### 3.3 各服务配置说明（yaml 字段逐一说明）

所有服务配置统一放在各服务目录的 `etc/` 下（`restart.sh` 以 `<服务目录>/etc/<服务名>.yaml` 启动）。仓库已附带可用配置与 `*.example.yaml` 模板。

**① 网关 `etc/datacenter-api.yaml`**（容器化对应 `deploy/docker/datacenter-api.docker.yaml`）

| 字段 | 当前值 | 说明 |
|---|---|---|
| Name | datacenter-api | 服务名 |
| Log.Mode | console | 日志输出到 stdout（nohup/docker logs 收集） |
| Host / Port | 0.0.0.0 / 8887 | 监听地址与端口 |
| Auth.AccessSecret | ad87xxxxxxx5d54b7d | **JWT 签名密钥，必须与 sys/rpc/etc/sys.yaml 的 JwtAuth.AccessSecret 完全一致**；生产必须更换 |
| Auth.AccessExpire | 86400 | token 有效期（秒） |
| CacheRedis[0].Host/Pass/Type | 127.0.0.1:16379 / admin / node | 网关缓存 Redis；**注意：仓库自带配置按开发机环境写的 16379**，用 server.sh 起的 redis 实际是 6379，需改成 6379（或把 redis 映射到 16379） |
| UserRpc/CommonRpc/VotesRpc/SearchRpc/QuestionsRpc/DataSourceRpc/MetadataRpc/DataSvcRpc/CatalogRpc/QualityRpc/MetricRpc/TagRpc/JobRpc/IdeRpc/AiRpc/StandardRpc/MdmRpc/OpsRpc/ThemeRpc/SecurityRpc/SysRpc | Etcd.Hosts=127.0.0.1:2379，Etcd.Key=各自 *.rpc | 各下游 RPC 的 etcd 发现配置；Key 与对应服务 yaml 的 Etcd.Key 一一对应 |

**② 通用 RPC 模板（datasource/metadata/datasvc/catalog/quality/metric/tag/job/ide/ai/standard/mdm/ops/theme/security）**，以 `datasource/rpc/etc/datasource.yaml` 为例：

| 字段 | 当前值 | 说明 |
|---|---|---|
| Name | datasource.rpc | 注册到 etcd 的服务 Key |
| ListenOn | 0.0.0.0:8085 | gRPC 监听（各服务端口见 §1.2） |
| Etcd.Hosts | 127.0.0.1:2379 | etcd 地址 |
| Mysql.DataSource | root:admin@tcp(127.0.0.1:3306)/datacenter?charset=utf8mb4&parseTime=true&loc=Asia%2FShanghai | 业务库 DSN；MySQL 8.4 如遇 Public Key Retrieval 报错，追加 `&allowPublicKeyRetrieval=true`（生产建议 TLS） |

差异化字段：

| 服务 | 额外字段 | 说明 |
|---|---|---|
| datasource | EncryptKey: 0123456789abcdef0123456789abcdef | 数据源凭证 AES-GCM 加密密钥（32 字节），**生产必须更换** |
| datasvc | CacheRedis（127.0.0.1:16379/admin）、EncryptKey | 结果缓存 + API 出口脱敏/凭证加密密钥 |
| quality | 无额外 | 规则/任务/告警全落 MySQL |
| ai | Llm.Enabled: false | true 时启用 LLM 生成 SQL（LLM 对接待真实环境联调，见 issue #23） |
| search | CacheRedis + Esconfig.Urls/User/Password | ES 连接（http://127.0.0.1:9200，elastic/admin） |
| sys | JwtAuth.AccessSecret/AccessExpire | 签发管理台 JWT，**必须与网关 Auth.AccessSecret 一致** |

**③ 遗留服务**：user/rpc/etc/rpc.yaml（127.0.0.1:8080，依赖 CommonRpc）、common/rpc/etc/rpc.yaml（8081）、votes/rpc/etc/rpc.yaml（8082）、questions/rpc/etc/rpc.yaml（8084）——均为通用模板结构。

### 3.4 日志位置

| 部署方式 | 日志位置 |
|---|---|
| 传统部署（restart.sh） | 网关：仓库根目录 `nohup.out`；各 RPC：`<服务>/rpc/nohup.out`（如 `quality/rpc/nohup.out`、`user/rpc/nohup.out`）。常用：`tail -F nohup.out`、`tail -F quality/rpc/nohup.out` |
| compose 部署 | `docker compose logs -f <服务名>`（datacenter-api/datasource/.../mysql/redis/etcd/elasticsearch） |
| DataEase（外挂） | 宿主机 `./data/dataease/logs/` |
| DolphinScheduler（外挂） | 宿主机 `./data/dolphinscheduler/` |

> 所有 Go 服务 `Log.Mode: console`，日志即标准输出；如需文件轮转，建议在传统部署中用 logrotate 对 nohup.out 截断，或改用 `Log.Mode: file` + `Log.Path`（go-zero 原生支持，需自行评估）。

## 4. 前端部署

### 4.1 开发/演示模式（Vite dev server，端口 5173）

```bash
cd web
npm install          # 依赖：vue3/element-plus/echarts/pinia 等（package.json）
npm run dev          # 监听 0.0.0.0:5173
```

前端直连网关（网关已开 CORS，不经 vite 代理）。后端地址由 `web/src/api/http.ts` 的 `baseURL` 决定，默认 `http://localhost:8887`，可用环境变量覆盖：

```bash
echo 'VITE_API_BASE=http://<网关IP>:8887' > web/.env.local
```

### 4.2 生产构建与静态托管

```bash
cd web
npm run build        # 产物在 web/dist（vue-tsc 类型检查可先跑 npm run typecheck）
```

用 Nginx 托管 dist 并反代网关（示例，可按客户环境调整）：

```nginx
server {
    listen 80;
    server_name dc.example.com;

    root /opt/datacenter/web/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # 前端为 hash 路由，/index.html 兜底即可
```

## 5. 升级指南

### 5.1 schema 增量执行顺序（新版本交付必读）

全部 schema 均为 `CREATE TABLE IF NOT EXISTS` 幂等语句，重复执行安全。**必须按以下顺序执行**（新装与升级同一顺序）：

```
sql.sql                          # 平台基座（遗留业务表）
→ docs/schema/phase1.sql         # dc_datasource/dc_meta_*/dc_api/dc_api_app/dc_api_grant/dc_asset*
→ docs/schema/phase2.sql         # dc_quality_rule/dc_quality_job/dc_quality_result/dc_metric/dc_metric_rel/dc_tag_*
→ docs/schema/phase3.sql         # dc_sync_task/dc_ide_script/dc_ask_log（Phase 3/4）
→ docs/schema/phase5.sql         # dc_std_*/dc_mdm_*/dc_ops_*（Phase 5）
→ docs/schema/phase6.sql         # dc_theme_*/dc_sec_*/dc_tag_group（Phase 6）
→ docs/schema/phase7.sql         # dc_quality_alert_channel/dc_quality_alert_log/dc_quality_error_data/dc_quality_profile/dc_api_call_log（Phase 7）
→ docs/schema/sys.sql            # sys_user/sys_role/sys_menu/sys_user_role/sys_role_menu（Phase 7 RBAC）
→ docs/demo/demo_data.sql        # 可选：演示数据（dm_* 前缀，与平台表隔离，可重复执行）
```

> 仓库不存在 phase4.sql：Phase 4（AI 问数审计）的表随 phase3.sql 一起交付（`dc_ask_log`）。

**升级操作**：

```bash
# 1) 备份（务必先备份，见 03-运维手册 §2）
mysqldump -uroot -padmin --single-transaction --routines datacenter > backup_$(date +%F).sql

# 2) 逐个执行新增 schema（已存在的表自动跳过）
mysql -uroot -padmin datacenter < docs/schema/phase5.sql
mysql -uroot -padmin datacenter < docs/schema/phase6.sql
mysql -uroot -padmin datacenter < docs/schema/phase7.sql
mysql -uroot -padmin datacenter < docs/schema/sys.sql

# 3) 重启服务（compose / 传统）
sh restart.sh                  # 传统
# docker compose build && docker compose up -d   # compose
```

### 5.2 compose 环境补齐 Phase 5-7 六个服务（全功能交付）

compose 镜像只含 11 个二进制，Phase 5-7 服务需在宿主机以传统方式补起（与 compose 共用同一 MySQL/Redis/etcd 时注意网络与配置）：

```bash
# 1) 让 compose 的 mysql/etcd/redis 对宿主机可达（临时加端口映射或用 docker compose port 取得映射）
# 2) 在宿主机按 §3.2 导入 phase5/6/7/sys schema
# 3) 修改对应 etc/*.yaml 指向 compose 依赖地址后启动：
cd standard/rpc  && go build -o standard-server ./standard.go && nohup ./standard-server -f $(pwd)/etc/standard.yaml &
cd mdm/rpc       && go build -o mdm-server ./mdm.go         && nohup ./mdm-server -f $(pwd)/etc/mdm.yaml &
cd ops/rpc       && go build -o ops-server ./ops.go         && nohup ./ops-server -f $(pwd)/etc/ops.yaml &
cd theme/rpc     && go build -o theme-server ./theme.go     && nohup ./theme-server -f $(pwd)/etc/theme.yaml &
cd security/rpc  && go build -o security-server ./security.go && nohup ./security-server -f $(pwd)/etc/security.yaml &
cd sys/rpc       && go build -o sys-server ./sys.go         && nohup ./sys-server -f $(pwd)/etc/sys.yaml &
# 4) 重启网关使其经 etcd 发现新服务（懒加载，通常无需重启即可被调用）
```

### 5.3 版本升级核对清单

1. `go.mod` go-zero 版本与目标一致；`go build ./... && go vet ./... && go test ./...` 全绿。
2. 新增接口后网关 `internal/handler/routes.go` 是否注册、`etc/datacenter-api.yaml` 是否补对应 Rpc 发现配置。
3. JWT 双端一致：网关 `Auth.AccessSecret` == sys 服务 `JwtAuth.AccessSecret`。
4. schema 已按 §5.1 顺序补齐（`SHOW TABLES LIKE 'dc_%'` / `LIKE 'sys_%'` 核对）。
5. 冒烟：登录 → 数据源 → 采集元数据 → 建 API → 发布 → 执行 → 质量任务（对照 04-SLA与培训.md §3 验收清单）。

## 6. 回滚预案

### 6.1 应用回滚（不动数据）

```bash
# compose
git checkout <上一个发布 tag/commit>
docker compose build && docker compose up -d

# 传统
git checkout <上一个发布 tag/commit>
sh restart.sh
```

> 应用与 schema 兼容策略：全部建表语句为 `IF NOT EXISTS` 幂等式，旧版本代码遇到新表不影响运行（多出的表不使用），因此**应用可以先回滚，schema 不必回滚**。

### 6.2 数据回滚（确需回退 schema/数据时）

```bash
# 1) 停写：停服务（防回滚期间继续写库）
docker compose stop datacenter-api datasource metadata datasvc catalog quality metric tag job ide ai   # compose
pkill -f '\-server' ; pkill -f datacenter-server                                                        # 传统

# 2) 恢复最近一次全量备份
mysql -uroot -padmin -e "CREATE DATABASE IF NOT EXISTS datacenter_bak"
mysql -uroot -padmin datacenter_bak < backup_$(date +%F).sql     # 先恢复到影子库校验
mysql -uroot -padmin -e "DROP DATABASE datacenter; CREATE DATABASE datacenter DEFAULT CHARSET utf8mb4;"
mysql -uroot -padmin datacenter < backup_$(date +%F).sql

# 3) 按需重放 binlog 增量至指定时间点（见 03-运维手册 §2.3）

# 4) 重启服务并冒烟
sh restart.sh
```

### 6.3 中间件回滚

| 组件 | 方法 |
|---|---|
| etcd | 服务注册为临时态，重启即恢复；异常时 `docker compose rm -sf etcd && docker compose up -d etcd`（服务重连自动重注册） |
| Redis | 仅缓存（结果缓存/验证码），清空无数据损失：`docker exec -it redis redis-cli -a admin FLUSHALL` |
| MySQL | 恢复 `./data/mysql` 冷备（需先停容器）或走 §6.2 逻辑备份恢复 |
| ES | search 为遗留独立功能，回滚容器即可；索引可重建 |

### 6.4 回滚演练要求

交付验收前应完成一次完整演练：全量备份 → 升级 schema → 冒烟 → 模拟故障 → 应用回滚 → 数据回滚 → 冒烟通过，演练记录留存（模板见 04-SLA与培训.md §3）。
